# Lab 6 — Secure Deployment Environment — документация: Студент 1

**Файл:** `linux_review_student1.sh`
**Целевая система:** Debian 13 «Trixie».
**Покрытые области раздела «System Review Example»:** раздел 4 методички — OS, Kernel, Time, Packages, Logging.

Инструмент построен по образцу LinPEAS с ограниченным объёмом. **LOTL-подход**: используются только штатные команды, файлы открываются на чтение, система не изменяется — скрипт только **находит и репортит** небезопасные настройки. Каждая проверка выводит статус `[ OK ]` / `[WARN]` / `[FAIL]` / `[INFO]`, в конце — сводка. При запуске скрипт определяет, загружена ли система с systemd и не работает ли внутри контейнера, и корректирует проверки.

## `check_os` — Операционная система
Определяет дистрибутив и версию (`/etc/os-release`, fallback на `/etc/debian_version`) и по major-версии оценивает поддержку.
**Проблема:** версия ОС вне поддержки не получает исправлений безопасности. Debian 13 — `[OK]`, Debian 11 — `[WARN]` (LTS до 2026-06), Debian 6–10 — `[FAIL]` (EOL).

## `check_kernel` — Ядро
Выводит версию ядра (`uname`) и uptime (`/proc/uptime`).
**Проблема:** старое ядро содержит известные CVE; большой uptime означает, что ядро давно не обновлялось (обновление требует перезагрузки). При uptime > 30 дней — `[WARN]`. В контейнере отмечается, что ядро и uptime относятся к хосту.

## `check_time` — Управление временем
Проверяет таймзону (`timedatectl`/`/etc/timezone`) и активность службы синхронизации (`systemd-timesyncd`/`chrony`/`ntp`).
**Проблема:** неверное время ломает корреляцию логов, проверку TLS-сертификатов и аутентификацию по времени. Для сервера рекомендуется UTC (без перехода на летнее время). Не-UTC таймзона — `[WARN]`; отсутствие NTP — `[FAIL]` (или `[INFO]` в контейнере, где время синхронизирует хост).

## `check_packages` — Установленные пакеты
Считает пакеты (`dpkg -l`) и ищет графическую среду, легаси-сервисы с передачей пароля открытым текстом (telnet, rsh, tftp, finger) и средства сборки.
**Проблема:** каждый лишний пакет расширяет поверхность атаки. Легаси-сервисы — `[FAIL]`, графическая среда — `[WARN]`, компиляторы — `[INFO]`.

## `check_logging` — Логирование
Проверяет `systemd-journald` (активность и постоянство хранения — каталог `/var/log/journal`) и `rsyslog` (запущен ли демон; чтение `/etc/rsyslog.conf` — настроена ли отправка логов на удалённый хост `@`/`@@` и права на лог-файлы `FileCreateMode`).
**Проблема:** без постоянного и удалённого логирования логи теряются при перезагрузке или их стирает злоумышленник. Volatile-журнал и отсутствие удалённого логирования — `[WARN]`; права лог-файлов, читаемые всеми, — `[WARN]` (рекомендуется `0640`).

## Запуск

На системе напрямую:
```
chmod +x linux_review_student1.sh
sudo ./linux_review_student1.sh
```

В Docker (Debian 13 Trixie):
```
docker build -t lab6-audit .
docker run --rm lab6-audit
```

Примечание: внутри контейнера systemd не запущен, поэтому проверки `journald` пропускаются, а отсутствие NTP помечается как `[INFO]` — это задача хоста. Для полного прогона всех проверок запускайте скрипт на системе Trixie с systemd.
